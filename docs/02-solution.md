# 方案

CLI 组装模型、仓库和服务。服务反复将历史与观察结果交给模型，执行 `search_documents` 或 `read_passage`，直到模型结束或工具调用达到上限。引用必须是本轮已读取片段的非空子串。工具故障返回未完成。

本地仓库按主题词检索；Milvus 仓库复用 BGE 混合检索、HyDE 和 RRF，再用本地 BGE Reranker 对完整片段评分并沿用旧版动态 Top-K（1～10 条、绝对分差 0.5 或相对分差 0.25）。重排失败记录日志并回退 RRF 顺序；分数截断可能漏掉相关的冲突资料。检索结果提供完整候选片段供模型判断；引用前仍须调用读取工具核对当前版本并登记证据。LangChain Core 1.2.19 与 langchain-openai 1.1.11 用于调用兼容模型；项目已安装 LangGraph 1.1.2，但本链路使用显式循环。Mock 是确定性规则，用于验证流程。模型使用 JSON 动作协议，工具执行和上限由服务控制。

网页导入将版本记录保存在 MongoDB，片段和版本标识保存在 Milvus。新版本完整写入后，通过原子条件更新切换当前版本；失败或竞争失败时保留原版本。每次问答固定版本快照，搜索和片段读取均校验当前版本。不同文档独立管理，因此不同制度的冲突仍可被发现；旧的无版本标识片段按 V1 兼容。历史片段暂不清理，也暂不支持回滚。

PDF 导入使用 MinerU 内容列表的 `page_idx` 按页切分，片段存储一基物理页码；各版本在 MongoDB 记录原文件相对位置。读取片段时仅对存在原文件的已发布版本生成访问链接，最终引用使用读取结果中的页码和链接，模型无法覆盖。旧资料及解析结果缺少可靠页码时不猜测；物理页码与印刷页码可能不同，浏览器 PDF 跳转依赖阅读器支持。

网页问答使用异步模型调用；同步仓库、PDF 解析和向量计算在线程中运行。普通召回与 HyDE 生成并发，先固定版本快照，再完成两路召回和融合。共享 BGE 模型由进程内锁保护，ReAct 决策仍按工具结果顺序进行；导入后台任务不具备跨进程持久化能力。

导入任务将状态保存在进程内，工作线程在状态变化时通知 SSE 订阅者；连接时先读最新快照，之后推送变化，并定时发送心跳。前端断线后可用状态接口确认结果并重新连接；完成和失败均关闭连接。旧版查询页的健康连接也通过 SSE 检测。

有对话历史且使用真实模型时，先用最近六条用户和助手消息改写追问，再将改写问题和原始历史交给决策循环。改写结果与状态记录在响应的 `query_rewrite` 中；无历史时跳过，改写失败则保留原问题与历史继续处理。改写不是证据，最终引用仍须来自实际读取的片段；模型仍可能改写错误或生成无效引用。

检索可能漏召回；模型可能误判冲突或生成不受原文支持的推论。子串校验不能替代语义判断或权限控制。
